## 三、设计的缺陷详情

### 3.1 并发与锁（评价：良好）
- `cache.md` §7 锁清单（`_cache_lock`/`_neg_lock`/`_feed_cache_lock`/`_feed_fetch_locks_lock`）+ 锁序纪律（互不嵌套、网络 IO 永不持锁、`event.set()` 在释锁后）；段 3 先出 `_cache_lock` 再取 `_neg_lock`——**无锁序风险**，符合项目"分锁不用全局大锁"约定。
- `metrics.md` 单锁 + 叶子锁 + 允许嵌套方向（`_cache_lock`→`metrics._lock`，反向禁止）明确；`incr` 的读-改-写在锁内 ⇒ MET-T6（100×1000=100000）可白盒断言。
- 遗留：REV-DES-05（`_warned` 锁内外表述不一致，无害）。

### 3.2 异常与降级（评价：良好）
- `FetchError(kind)` 枚举封闭（构造期拒绝非法 kind，禁止自由文本入 `_errors`），`raise ... from exc` 保留异常链；`build_batch_response` 为**总函数**（不抛）；`fetch_json` 失败**恒为 `FetchError`**（不再 `RuntimeError`/返回 `None`）。
- 全路径有界：删除 fall-through（13.5s 来源）、follower 不重入选举、gap 分支 fail-closed（不触网）。
- 遗留：REV-DES-09（段 3 try 范围过宽）。

### 3.3 数据模型与值域（评价：良好）
- 值域三分（成功/无数据/失败）唯一判别式钉死；`_errors` 仅在"值 null ∧ errors 非空"时挂载；`_truncated`/`_dropped_count` 仅 `dropped>0` 同现（≤50 两键均不存在，AC-A9 单一口径）；批量响应永不含顶层 `error`（与单体形态互斥，AC-A5）。
- 负缓存条目 `{until, kind, fail_count}`、URL 缓存 `{data,time,last_access,expires_at}`、`DOMAIN_MATRIX` 11 域全表实值——**无占位、无二义**。

### 3.6 ⚠️ 逆向审查（反证 / 遗漏 / 不可逆 / 断链）
- **⚠️ 逆向审查（半开探测"永久 2s 陷阱"）**：BR-CACHE-7/8 规定失败历史仅在"成功"或"满额淘汰"时清除。若某 URL 失败一次后上游恢复但**变为"慢而 >2s 才成功"**，该 URL 将**永久停留在 `PROBE_TIMEOUT=2s` 探测预算** → 每次探测超时 → 永不成功 → 历史永不清除，与 AC-E2（正常回源 P95≤1.2s/P99≤3s）长期互斥。ADR-003 接受了负缓存延迟，但未覆盖"慢而成功"的长期退化。**建议**：为失败历史增加老化口径（如 `until` 过期超过 K×`NEG_TTL` 且期间无新失败 → 视同无历史），或至少登记该风险与 AC-E2 的交互。**关联 AC-E2/S3。**
- **⚠️ 逆向审查（不可逆：删常量=进程级不可用）**：config 常量删除后未同步消费者即 `ImportError`（整进程不可用）。详设已要求"同一 change-set"，但本批只有 config/cache/metrics 三份，stock_api/server/market_api 详设**尚未产出**。**建议编排层**：将 config.py 常量删除**延后**到全部消费者详设齐备，或先"双轨"（保留旧常量 + 新增 policy）一版再删，避免中间态崩溃。
- **⚠️ 逆向审查（误导：冻结注册表的运行时真空）**：`metrics.md` BR-MET-3"未注册名仍写入（仅 warning）"使"注册表冻结"失去运行时强制；一个拼写错误会产出"看着有、实际错"的假指标（AC-S10 要求可观测到**指定**项）。**建议**：MET-T8 加强为"全量运行后 `snapshot()` 键集合 ⊆ 注册表"，并在 `metrics.md` §10 说明"冻结=文档契约，运行时仅告警"。
