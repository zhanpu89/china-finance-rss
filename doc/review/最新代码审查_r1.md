## P2 问题

### P2-1 测试重复定义与死代码（`tests/test_stream.py`）
**证据（AST 扫描）**：
```
BroadcastGhostReserveTests.test_sweep_reconnect_race_stress_no_kill: 定义于行 [2022, 2053]
```
- 同类内同名定义两次（实现不同但功能等价：docstring 分别为"无崩溃/死锁/误杀"与"注册成功即受保护"），**Python 后者静默覆盖前者 ⇒ 行 2022 的实现永不执行**（死测试）
- 另：两个 sweep 测试同时出现在 `ZombieGroupTests`（语义相符）与 `BroadcastGhostReserveTests`（主题为 broadcast ghost reserve，**语义不符 + 冗余**）
- **影响**：无覆盖损失（等价实现 + 另一类有同名测试），但制造"看似覆盖两次实为一次"的假象，且疑似**同一 patch 被应用两次**的合并痕迹
- **建议**：删除 `BroadcastGhostReserveTests` 中的重复对，仅保留 `ZombieGroupTests` 版本

### P2-2 gzip `Accept-Encoding` 解析不严谨（`server.py:_send_text`）
**证据（实测）**：
```
Accept-Encoding='gzip;q=0'  -> gzip   ← 客户端明确拒绝，仍压缩（违反 RFC 9110）
Accept-Encoding='GZIP'      -> raw    ← content-coding token 应大小写不敏感
Accept-Encoding='*'         -> raw    ← 应视为接受任意编码
```
- 现实现为 `'gzip' in header`（子串匹配），无法表达 q=0/大写/通配
- **建议**：按 `,` 分割、剥离 `;q=`、token 小写归一、支持 `*`、排除 `q=0`

### P2-3 gzip 协商时 `Vary: Accept-Encoding` 仅在 `cache=True` 分支发送
**证据（实测，`/ths/longhu`）**：
```
Content-Encoding: gzip
Content-Length: 21922
（无 Vary、无 Cache-Control —— cache=False 路径）
```
- 受影响路径：`/`（首页 HTML）、`/healthz`、`_send_error`（均 `cache=False`，且首页/healthz 可 >1KB）
- **风险**：中间缓存/代理可能把 gzip 体回给不支持 gzip 的客户端
- **建议**：只要 `gzipped` 为真，**无条件**发 `Vary: Accept-Encoding`（移出 `if cache:` 分支）

### P2-4 CDP 页面内存假设不一致
- SAD `R20`/`§4.3` 按「每页 **150MB+**」估算内存总账；部署文档按「**50-100MB/tab**」估算 —— 相差 1.5–3×
- 现默认 `CDP_STOCK_PAGES=4` + 2 常驻 = 6 页：按 SAD 口径 ≈900MB（贴近 `mem_limit 1.5g`），按部署口径 ≈300–600MB
- 且 SAD 内存总账仍按 `CDP_STOCK_PAGES` **默认 3** 表述（compose 已改 4）
- **建议**：统一单页内存口径，并在 SAD 内存总账中更新为 `CDP_STOCK_PAGES=4` 基线

### P2-5 `Dockerfile` 与 `docker-compose.yml` 的 `MAX_WORKERS` 不一致
- `Dockerfile:23` `ENV ... MAX_WORKERS=10`；`docker-compose.yml` `MAX_WORKERS=20`（压测基线基于 20）
- 直接 `docker run`（不经 compose）会拿到 10，与文档所载压测基线不符
- **建议**：Dockerfile 同步为 20，或加注释说明差异

### P2-6 `config.py` GZIP 常量插入位置割裂注释
- `GZIP_MIN_BYTES`/`GZIP_COMPRESSLEVEL` 被插在「描述 `DOMAIN_MATRIX` 的 `'n/a'` 归一化（BR-CFG-11）」注释与 `DOMAIN_MATRIX` 定义之间，割裂原注释与矩阵的关联
- **建议**：上移/下移常量块，保持注释与所注对象相邻
