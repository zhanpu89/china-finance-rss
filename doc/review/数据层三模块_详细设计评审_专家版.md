## 三、设计的缺陷详情

### 3.1 并发与锁（评价：良好）
- `stock_api.md §7`：域锁（pool+cache+`cache_ts` 同域共享一把，复用既有）与新增 `_fail_ledger_lock` **互不嵌套**；记账后**释放自身锁再**调 `metrics`（`metrics._lock` 永远最内层）；网络 IO 全程不持锁。锁序纪律与 `cache.md §7.2` 一致，无死锁面。
- `cdp_engine.md §7`：`_chrome_restart_lock → _restart_window_lock → metrics._lock` 单向；`_publish_window()` 在释放 `_restart_window_lock` 后调用；`_restart_window_lock` 临界区仅字段读写。既有 `_chrome_restart_lock` 为 **RLock**（源码 cdp_engine.py:33 已核实），`full_chrome_restart → ensure_chrome` 重入安全。
- `market_api.md §7`：无模块级可变状态、无锁，天然线程安全；调用点均在锁外。
- 遗留：REV-DES-15（预算耗尽计入 ledger 的口径）、REV-DES-19（初始态未发布）。

### 3.2 异常与降级（评价：良好）
- 三层降级链闭合：URL 级负缓存（cache，5s）→ 码级冷却（stock_api，120s）→ 预算层 deadline（15/60s）→ 端点层组装（`build_batch_response` 总函数 / error 客体）。`None`（无数据）与 `_errors`（失败）**永不合并**，值域三分自洽。
- `handle_*` 全部返回 dict 不抛；`_fetch_one`/`_run_batch`/`build_batch_response` 均总函数；单码故障并发隔离（每码独立 try）。
- `cdp_engine.page_data` 为总函数（`None`/非 dict/空 dict/异常 → `None` + warning，绝不抛），A/A′ 降级的唯一信号源。
- 遗留：REV-DES-12/13/14（观测计数与防御细节）、REV-DES-18（page_data None 语义跨模块不一致）。

### 3.3 幂等与状态机（评价：良好）
- `cdp_engine §3.2` 转换表含 8 条迁移（含逆路径 `restarting/unavailable→idle`），幂等迁移不刷新 `window_start`；"节流受限的 `ensure_chrome()==False` 视为未尝试⇒不改状态"避免假 `unavailable`，是一处正确的防御性决策（对应 CDP-T7）。
- `_fail_ledger` 老化（BR-SA-8）实现"连续失败"语义并给账本有界（`≤ 5×2000`）。
- `_prefetch_slice` 不修改游标、由调用方 `_prefetch_advance` 推进，取切片与推进解耦——与 `stream.md` §10#7（临时轮转视图 + `'stream_refresh'` 键）一致，**契约成立**。

### 3.4 数据模型（评价：良好）
- 池（`code→ts` 成员账）与终点缓存（`OrderedDict` 数据 LRU + `cache_ts` 写入时刻）**解耦**：池淘汰仅 `del pool[code]`，数据内存由 `cache_max` 独立 LRU 守；`cache_ts` 命中不刷新（保 AC-A4 的 TTL 上界）。与 SAD §2.1 三层缓存表逐条一致。
- 失败账 4 元 `[fail_count, cooldown_until, kind, last_fail_ts]`；`code_cooldown_list` 元素仍为 `[domain, code, cooldown_until]`（与 metrics.md/SAD 一致）。

### 3.5 可观测性（评价：良好）
- 四指标（`cache_entries{domain}`/`code_cooldown_list`/`upstream_fetch_total{domain}`/`upstream_fail_total{kind}`）+ `cdp_restart_window` 均在 `metrics._KNOWN` 冻结注册表内；发布点均在各自锁外或释放后。遗留 REV-DES-12/13/19/20（计数完整性与初始发布）。
