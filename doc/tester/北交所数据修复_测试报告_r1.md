## 五、口径说明（与任务描述的两点偏差，均不影响验收）

1. **端点口径：** 任务 3A 写的是 `curl /stock/data?code=$c` 并要求含 `secu_name`/`last_px`。核对路由后确认 `/stock/data` → `handle_cls_stock_batch`（个股**详情**，返回 `label`/`plate`/`primary_industry`，本就不含 `secu_name`/`last_px`）；承载 `secu_name`/`last_px`/`depth` 的是 `/stock/basic_info`（→ `handle_cls_basic_infos`）。故 3A 的行情验收改用 `/stock/basic_info`，同时保留 `/stock/data` 的详情回归（沪深/北交所均真实）。
2. **改动点数：** 代码中 x-quote `secu_code` URL 构造为 **9 个唯一站点**（basic / detail / depth / fundflow / timeline / announcement builder / basic 阶段 2 detail / fundflow direct / timeline direct），其中 announcement builder 被 REST 与 CDP 直连两处调用 ⇒ 按调用点计 **10 处**，与提交信息一致。无遗漏站点（`server.py:390` 的 `secu_code` 属板块码 `cls*`，非个股码；`cdp_engine` 仅用 `canonical_code` 做内部比对）。
3. **时延观察（非缺陷）：** SSE 首次投递真实帧受 tick 网格 + 冷启动影响，个别连接前几秒仅收到 `event: ping` 心跳（无 `items`）。本次 22s 窗口内稳定取得含 `items` 的真实帧，符合「观察 ≥1 帧」验收。标注为观察项，未升级为缺陷。
