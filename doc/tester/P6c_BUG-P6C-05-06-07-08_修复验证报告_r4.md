### 3.2 ⚠️ 关键发现：网格对齐只保证「轮起点」，帧交付仍继承刷新耗时抖动

实测 `115.21s` 而非 `120s`，可精确归因：

```
交付间隔 = tick + d_next − d_cur      （d = 该轮刷新耗时）
120 + 0.309 − 5.104 = 115.205  ←→  实测 115.21  ✅ 完全吻合
```

- 首轮冷启动 20 码 quote 耗时 **5.104s**，次轮缓存命中仅 **0.309s**；
- `_tick_sleep_seconds` 把**轮起点**钉在 `t0+k×tick` 网格（已用纯函数复核：sleep 8.00→2.90→2.90 严格落网格），但**帧交付时刻 = 轮起点 + 刷新耗时**，故交付间隔仍带 ≈4.8s 抖动。
- **外推到 tick=8（交易时段）**：

| 相邻轮 | 交付间隔 = 8 + d_next − d_cur | 判定 |
|---|---|---|
| 冷→暖 | 8 + 0.309 − 5.104 = **3.205s** | ❌ **< 4s，违反「无 <4s 重复帧」** |
| 暖→暖 | 8.000s | ✅ |
| 暖→冷 | 12.795s | ⚠️ 接近 >12s 上限 |

> 即：**冷启动→缓存转暖的一次跳变**会产出 ≈3.2s 的背靠背帧。这与 r3 观察到的「2s 背靠背」同源，修复只是把下限从 `0.25×tick(2s)` 抬到「网格起点」，**并未消除交付层的短间隔**。
> 该结论为**基于实测耗时的推导（DERIVED）**，非交易时段实测；**须在 13:00 CST 后于 tick=8 复测确认**。

## 5. lag gauge 归零验证（BUG-P6C-08）❌ **未闭环**

### 5.1 实测

1. 建组 **200 码 × (quote,fundflow)** → C2 分片 → healthz `stream_refresh_lag_ticks = 2`（>0，正常有积压）
2. **DELETE 全部订阅组**（日志确认 `group 3bb93363a17f destroyed`），随后 **150s 内每 10s 采样**
3. 结果：

```
lag 采样序列（t 从删除起算）：
0s:2  10s:2  20s:2  30s:2  40s:2  50s:2  60s:2  70s:2  80s:2
90s:2 100s:2 110s:2 120s:2 130s:2 140s:2
distinct_lag_values = [2]      ← 从未出现 0
lag_final = 2
期间 tick_ms = 0.03 / 0.11（空池特征）  ← push_loop 确实在跑，且池已空
```

- 空池期间 `push_loop` **确实在运行**（tick_ms 掉到 0.03ms = 空池轮），150s 覆盖 **≥2 个 120s tick**，`lag` **始终滞留 2**。
- 会话结束后再次确认：`stream_frame_distinct=0`、`tick_ms=0.02`、**`lag=2`** —— 与 r3 观察到的「滞留 17」同症状。

### 5.2 根因（源码定位，已复核）

- `_refresh_pool` 内的空池归零分支在 **stream.py:299**（`n == 0` → `set_gauge('stream_refresh_lag_ticks', 0)`）；
- 但 `_refresh_pool` **全工程仅一个调用点**：**stream.py:633**，且被 **line 632 `if codes:`** 守卫：

```python
codes, fields = _active_targets()
if codes:                                  # ← 空池时整体跳过
    snapshot = _refresh_pool(codes, now, fields)
    _broadcast(snapshot)
```

- 池空 → `_active_targets()` 返回 `(set(), [])` → `if codes:` 为假 → **`_refresh_pool` 永不执行 → line 299 的归零是死代码**。
- 因此 `stream_refresh_lag_ticks` 一旦在 C2 轮被置为 >0，此后**无任何路径**可复位（该 gauge 仅 299/341 两处写入）。

### 5.3 单测为何假绿（测试完整性缺口）

`RefreshLagGaugeTests.test_empty_pool_publishes_zero_not_the_stale_value`（test_stream.py:875）：

```python
stream_mod.metrics.set_gauge('stream_refresh_lag_ticks', 17)
self.assertEqual(_refresh_pool([]), {})          # ← 直接调用函数
self.assertEqual(self._lag(), 0)
```

- 它**直接调用 `_refresh_pool([])`**，绕过 `push_loop` 的 `if codes:` 守卫 → 断言成立、测试常绿；
- 但真实调度路径**永远走不到**该分支 → **绿测试掩蔽坏系统**。
- 修法（供参考，本报告不改码）：把归零发布上提到 `push_loop` 的 `else:`（空池分支），或把守卫改为「仅在无订阅且 gauge 非 0 时发布 0」。
