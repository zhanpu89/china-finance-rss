# 测试用例文档模板

每个模块独立文件：`doc/tester/{模块名}_测试用例.md`。

## 头部

```
TC-{YYYYMMDD}-{NNN} | 版本 v1 | 状态 🟡草稿 | 日期 | 作者(agent) | 关联详设 {模块}_详细设计.md
```

多轮评审修复版本递增，状态 🟡草稿 → 🟢确认。**禁止直接写 🟢，确认后才改状态**。

## 一、测试范围与追溯

| 详设 BR/接口 | 覆盖用例 ID | 类型分布 |
|-------------|------------|---------|
| §2 BR-001 (创建订单) | TC-ORD-UNIT-001, TC-ORD-INTG-001 | ... |

**追溯完整：每条 BR 和每个 OpenAPI 端点都至少要出现在此表一次。** 出现 0 次 = 漏测，此处自检。

## 二、用例表

| ID | 类型 | 标题 | 方法 | 优先级 | 前置条件(含数据) | 测试步骤 | 预期结果(可判定) |
|----|------|------|------|--------|-----------------|---------|-----------------|
| TC-{模块}-{类型}-{序号} | UNIT/INTG/SEC/PERF/FE | 一句话动作+对象 | 等价类/边界/状态迁移/场景/判定表/路径 | P0-P3 | 明确状态+数据+mock | 步骤化 | 具体值,非"应该正常" |

**ID 规则：** 模块缩写(2-4字，用 `-` 或字母) + 类型缩写(UNIT/INTG/SEC/PERF/FE) + 序号(001起)。

**类型映射：**
| 类型 | 对应详设节 | 用例要求 |
|------|-----------|---------|
| UNIT | §2 业务规则 / §4 伪代码 | 每 BR 正反各 1；伪代码每分支 1 |
| INTG | §3 OpenAPI | 每端点正常 + 异常（错误码齐全） |
| SEC | §10 安全 | 注入/越权/敏感泄漏/幂等 |
| PERF | §9 性能 | 峰值量级下响应与吞吐 |
| FE | 前端交互 | 字段级双向核对、前端路径、组件状态 |

## 三、P0/P1 阻断标记

- 代码评审 P0/P1 → 专项用例标 `[评审专项]`。
- 含 P0 用例的模块，结论节必须 ❌ 阻断，禁止放行。

## 四、结论节（文档末尾）

```
结论: ✅ PASS≥90% / ⚠️ PASS≥80% / ❌ 有P0或PASS<80%
未通过用例: TC-... (附 BUG-{模块}-{序号} 关联)
Flaky 用例: ID (次数) / 备注
```
