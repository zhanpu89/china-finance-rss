# 测试设计方法论与质量标准

> 本文档是测试工程师的"六板斧"与"实测基准"，不是检查清单。写用例前先通读，让它成为你的测试直觉。

## 一、六大测试设计方法（用例从哪来）

不要"绕文档找测试点"，用方法系统性导出，每类用例标注"来源方法"：

| 方法 | 适用 | 产出用例类型 |
|------|------|-------------|
| **等价类划分** | 任何有输入的范围字段 | 每个等价类至少 1 正 + 1 反（有效/无效等价类） |
| **边界值分析** | 数值/长度/时间范围 | min、max、边界±1、范围内一点（BVA ≤ min / = min / min+1 / max-1 / =max / >max） |
| **判定表** | 多条件组合决策（规则引擎/审批） | 条件×动作全组合，N 条件→2^N 行见真章，过大的降维合并 |
| **状态迁移** | 状态机（订单/审批流） | 每个合法迁移 1 正例；每个**非法迁移** 1 反例（尤其被禁止的路径） |
| **场景法** | 端到端业务流程 | 主成功流 + 备选流 + 异常流（覆盖失败/超时/重试/降级） |
| **路径覆盖** | 伪代码/核心算法 | 每个分支、每个异常路径各 1 例；关键路径达到行覆盖 |

**设计顺序：** 字段→边界→组合→状态→流程→算法。先用边界和等价类把输入关系搞清，再上状态和场景，方法不叠代则是遗漏信号。

## 二、异常层次模型（最容易漏的地方）

对一个功能，异常绝不只有"输入非法"。四层逆向问：

| 层 | 问什么 | 测试点 |
|----|-------|--------|
| **输入层** | 空/超长/格式错/XSS/SQL注入/越权字段 | 每个字段的非法值；注入载荷（`' OR 1=1--`、`<script>`）；水平/垂直越权 |
| **依赖层** | DB 挂/第三方 API 超时/缓存 miss/消息投递失败 | 依赖 party 不可用时的降级路径与错误码；重试间隔 |
| **时序层** | 并发/重复提交/幂等/脏读 | 并发双写同一资源；重复点击；事务回滚后状态正确 |
| **数据层** | 数据不存在/已被删/级联/唯一约束冲突 | 空结果集；孤儿记录；主外键冲突；字段超长截断 |

**法则：** 写用例时先列"它没说但一定会发生的"四层场景，再列详设写了的分支。**详设没写的分支最有价值。**

## 三、用例质量硬标准（每条约可判定）

- **预期可判定**：能答"通过/失败"，不是"应该正常"。用具体值（"返回 400 code=INVALID_PARAM"）。
- **独立原子**：一条用例不依赖另一条的执行顺序或共享可变状态。
- **有前置条件**：明确初始状态、mock 哪些依赖、需要哪些测试数据。
- **有测试数据**：前置里给出具体数据（订单、用户、token），不是"准备一条订单"这种含糊。
- **每条 BR 都有反例**，不只正例——正例保底，反例才是价值。

## 四、测试数据策略

- **单元测试**：fixture/factory 建隔离数据，用例结束清理；不用全局共享可变状态。
- **集成测试**：独立测试库，每轮结束重建基线；种子数据版本化。
- **共享 fixture**：标注共享，仅限无互相干扰的用例并行；有写冲突的必须隔离。
- **时间/随机数**：注入时钟与随机源（fake/mock），避免时间敏感用例 flaky。

## 五、Flaky 管理

- 失败先重试 1 次确认是否 flaky；**连续 2 次失败才报 BUG**。
- 报告标注 flaky 次数 > 1 的用例；排查根因（时序/数据污染/环境依赖）而非跳过。

## 六、覆盖率雷达（不是单看一个数）

| 维度 | 目标 |
|------|------|
| 需求逻辑 | 每条 BR/AC 有对应用例（追溯） |
| 行覆盖 | 关键路径 100%，单元 ≥80%，集成 ≥60% |
| 变异质量 | 反向用例能捕获明显变异（反例在，证明测试不是摆设） |
| 异常覆盖 | 异常/边界 ≥20%，性能 ≥5%，安全 ≥5% |

**质量不是用例总数，是"把断裂点都盖到"。** 用例过多但都在写正常路径 = 假覆盖，报告里自我提醒。

## 七、缺陷 ID 与分级

`BUG-{模块}-{序号}` + 关联用例 ID + 描述 + 复现步骤 + 严重度(P0-P2)，与 code-reviewer/review-expert 同一套表：
- **P0**：崩溃/数据丢失/资金错误/安全 → **立即暂停**，不改不继续
- **P1**：功能缺陷/单点/性能退化 → 生产版阻断；MVP 记入报告
- **P2**：可维护性/规范/测试自身问题 → 记录，不阻断

## 逆向检查（提交前）

- □ 每个输入字段有等价类正反例？
- □ 数值/范围字段做边界值分析？
- □ 状态/审批流非法迁移有反例？
- □ 四层异常（输入/依赖/时序/数据）都有覆盖？
- □ 每条用例可判定（不是"应该正常"）？
- □ P0 已阻断、缺陷按 BUG-ID 分级？
