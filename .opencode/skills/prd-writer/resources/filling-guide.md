# PRD 填写指南

Step 3 加载。本节只列**关键约束和常见陷阱**（这是评审会抓的点），标准 PRD 结构不在此重复。

## 执行摘要

`[产品] 是 [用户] 用于 [功能] 的 [类型]，解决 [痛点]`

## 目标

SMART（具体/可衡量/可实现/相关/有时限）。M/S 级功能有 Given/When/Then AC。

## AC 质量标准

| 维度 | 反例 ❌ | 正例 ✅ |
|------|--------|--------|
| 无技术描述 | Given 用户请求 GET /api/order | Given 用户在订单列表页 |
| 可观测 | Then 数据库写成功 | Then 页面显示"提交成功"提示 |
| 无歧义 | When 用户正确输入 | When 用户输入有效手机号并点击提交 |
| 单一场景 | When 用户操作 1 和操作 2 | 拆为 2 条 AC |

## 常见陷阱

- "用户可管理订单" → 拆分为 CRUD 逐条 M/S 级："用户可查看订单列表""用户可取消未支付订单"
- "系统自动处理" → 写明触发条件、处理逻辑、失败处理
- "支持多语言" → 明确是 UI 国际化还是内容多语言，第一期做哪些语言
- "实时" → 明确是实时推送还是轮询，延迟容忍度多少

## NFR 基准

未指定时按行业默认：
- Web 首屏 <3s，移动端 <2s
- API P99 <500ms（读）/<1s（写）
- 并发 = DAU × 日人均行为次数 × 峰值系数（建议 1.5）
- 可用性：MVP 99.9%（周 43min），生产 99.95%（周 5min）
