# 编排决策矩阵（Orchestration Decisions）

> 项目经理的调度本能不是一堆 case，是一套决策框架。本文件把 SKILL 中分散的并行/升降档/恢复/止损规则收敛成统一判定矩阵——**每个调度动作都有一个明确触发条件，不靠"感觉该并行了/该降档了"**。

## 一、并行 vs 串行（一切调度决策的起点）

**并行 ≠ 快，是可验证独立才快。** 先问三个问题，全 Yes 才并行：

| 判定 | Yes | No |
|------|-----|-----|
| 独立成败？ | 各组的产出不依赖对方结果即可评审/回归 | 后一组依赖前一组结论（如 P2a 依赖 P1c 签收）→ 串行 |
| 文件隔离？ | 各组改的文件无重叠、无共享模块 | 共享文件/同模块 → 串行合并 |
| 边界清晰？ | 每组 scope 明确到模块/文件，prompt 声明"禁止改他组文件" | 边界模糊 → 串行，先做边界探测 |

**并行度上限 3**（防上下文过载）。超过 3 组分批并行，不是 4+ 一起跑。

**可并行的典型：** 多模块 Bug 修复（按变更文件分组）、P6c 多模块 T1 回归、P3a 多份详设（互不依赖）。
**不可并行的典型：** P2a→P3a（详设依赖架构结论）、P1b→P1c（签收依赖评审结论）、文档同步 P7b（每类文档各有后置门禁）。

## 二、强度升/降档（自适应，非一次定死）

强度表是起点不是终点。每个 Phase 终了检查触发信号：

| 信号 | 触发条件 | 动作 |
|------|---------|------|
| **升档** | 同一 Phase 返工 >2 次；评审 P1 堆积（>阈值）；用户连续纠正 ≥2 次；实际范围比预估广（扫描时漏了 DDL/跨模块） | 强度表升一级，**重写 `_MEMORY_CACHE.md` 的 Phase 序列**，`add_decision()` 记录升档理由 |
| **降档** | 连续 3+ Phase 零返工零修正；P5b 无 P0/P1（P2 也有但很少）；实际范围比预估窄 | 强度表降一级（最低 🐛 不降），同步收窄 Phase 序列 |
| **幅度** | — | 一次只动一级，不跳级。升档后首个 Phase 严格跑全门禁验证"确实需要" |

**为什么升档要重写序列：** 强度表只在你首次分析时定一次——但任务中途发现实际复杂度超出预估，沿用原序列会漏 Phase。升档 = 把漏掉的 Phase 补回来，不是形式换档。

## 三、恢复路径选择（🅱 vs 🅲 的区分关键）

恢复表只有处理没有依据。核心判断：**先定位根因在"当前 Phase"还是"更早 Phase"**。

| 步骤 | 判断 | 走哪条 |
|------|------|--------|
| 1 | 门禁 exit 2？ | 🅱 评审未通过 |
| 2 | 产出质量差但门禁过了？ | 🅲 产出质量差 |
| 3 | **根因在更早 Phase？（P5b 发现契约错 → 根因是 P3a 详设，不是 P5a 代码）** | 回退到根因 Phase，不是只重做当前 |
| 4 | 2 次同质失败？ | 🅳 死循环：暂停 → 换策略/搜历史 → 仍不行报告用户 |

> 第三条是最常踩的坑：P5b 打回就只重派 code-developer，其实契约错误根因在详设——**重做当前 Phase 是原地打转，回退根因才是恢复**。

## 四、止损/熔断（统一阈值，一处定义）

| 场景 | 阈值 | 动作 |
|------|------|------|
| 单一 Bug 修复 | 同一 Bug 修 3 次仍不过（含并行组） | 停止该 Bug，报告用户，不无限重试 |
| P8 盲审 | 连续 2 轮仍发现 P0 | 输出未解决清单 → `_MEMORY_CACHE.md` → 报告用户 |
| 任意 Phase | 同一 Phase 重做 ≥3 次 | 熔断：暂停 → 报告用户，走 🅳 |
| 并行组 | 单组超过主流程 2 倍耗时 | 该组降串行继续，不等它拖慢整体 |

**止损不是一个 Bug 一个规则，是全链同一纪律：** 重试有上限，上限到了就报告，绝不静默无限循环。所有熔断都 `add_decision()` 留痕。

## 五、资源分配边界（上下文成本意识）

| 动作 | 边界 |
|------|------|
| 裁剪上下文 | 只带 `_MEMORY_CACHE.md` + 本 Phase 指令，前序推理不带到下一 Phase |
| 评审预取 | P5b/P8 前编排器收集 diff 摘要内联 prompt（省评审冷启动）；**并行分组用 `git diff -- <组路径>` 隔离** |
| P8 零上下文 | 只带需求原文路径 + 改动文件 + 变更范围 + `>>DIFF:` 客观摘要，禁带中间产物 |
| 镜像回写 | 只回写 ≥2 实现证实 + 有约束力的稳定模式，单次 hack 不回写 |

**资源分配原则：** 上下文是稀缺资源。能预取给 subagent 的就不让它自己探索，但**预取边界里夹带主观产物 = 污染评审**（P8 尤其敏感）。

## 六、自检（每轮 Bug-fix Loop 结束过一遍）

```
[  ] 每次并行都是"可验证独立"才并（三问全Yes）？不是 = 我为什么并行？
[  ] 强度升降都改写了 Phase 序列并 add_decision 留痕？只是口头换档不算数
[  ] 失败恢复先查了根因在哪个 Phase？没查 = 可能在原地打转
[  ] 任何重试都数到上限了吗？超上限我现在就报告用户，不拖到用户来问
[  ] 预取边界无主观产物泄漏进评审 prompt？P8 尤其自查
```
