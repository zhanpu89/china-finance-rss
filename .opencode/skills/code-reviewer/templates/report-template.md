# 代码评审报告模板

输出 `doc/review/{模块名}_代码评审报告{_RN}.md`。纯后端模式不含 Dim 0 和前端节。

## 报告结构

**头部：** CR-YYYYMMDD-NNN / 版本 / 状态 / 评审模式 / 日期 / 关联文档

**一、评审概要：** 结论(✅/⚠️/❌) / P0/P1/P2 数量 / 是否允许进入测试

**二、评审范围：** 后端文件清单 / 前端文件清单(全栈)

**三、问题清单：** ID / 等级 / 文件位置 / 问题描述 / 修复建议 / 阻断标记

**四、问题详情：**
- Dim 0（全栈）：契约一致性 — 后端覆盖率/前端字段一致性/小程序一致性/端间一致性
- Dim 1：数据与正确性 — 魔法数字/重复数据源/宽泛异常/隐式状态转换等
- Dim 2：并发 — 非原子读改写/未同步共享状态/双检锁陷阱等
- Dim 3：资源与性能 — N+1/大事务/资源泄漏/缓存穿透等
- Dim 4：安全 — 注入/越权/敏感泄露/明文密码等
- Dim 5：结构与可维护性 — 上帝对象/过度抽象/复制粘贴/圈复杂度等
- Dim 6（全栈）：前端审查（编码/逻辑/安全/性能/可维护性/框架特化）

**五、修复建议：** P0 应如何修复 / P1 建议修复方案 / 改进优先级

**六、评审结论：** ✅ 无P0且P1≤2 | ⚠️ 无P0但P1>2 | ❌ 有P0
