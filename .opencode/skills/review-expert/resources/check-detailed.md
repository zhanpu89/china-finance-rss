# 详细设计评审检查清单

> 检查锚点按详设模板章节映射。每项给"怎么查"，不依赖"AI 按标准实践执行"。

## 一、按章节的检查锚点（对照模板 12 节）

| 模板章节 | 查什么 | 怎么查 |
|---------|--------|--------|
| 1 功能描述 | 功能是否可验证 | 每个功能是否有一句验收断言（"当 X 则 Y"），无断言=P1 |
| 2 业务规则 | 规则是否精确到字段 | 每条 REG/BIZ 是否有取值范围/条件；"按需""合理"等模糊词=P1 |
| 3 接口 | 契约是否完整 | 每个接口有请求/响应/错误码/认证；入参出参字段逐一对齐 OpenAPI schema |
| 4 功能逻辑 | 并发与资源 | 伪代码是否含事务/锁/补偿/重试/超时标记；`TRANSACTION` 内是否有网络 IO |
| 5 状态机 | 逆路径完整性 | 每状态每事件的合法/非法迁移各一条；有无死状态（无出边） |
| 6 算法 | 边界与复杂度 | 核心算法有输入边界描述；含复杂度说明，非朴素遍历可省 |
| 7 DDL | 数据模型质量 | 主外键/唯一约束/索引有理由；字段命名规范；无 `SELECT *` 隐患 |
| 8-9 接口 | 依赖方向 | 模块间调用是否跨层；外部接口是否有超时/重试/降级描述 |
| 10 性能 | 量化 | 有 TPS/延迟/容量数字，且与 SAD 的 NFR 一致；无"性能好"裸词 |
| 11 安全 | 攻击面 | 认证/授权/输入校验/敏感字段处理逐一出现；越权场景有描述 |
| 12 依赖 | 依赖清单 | 依赖精确到模块+接口路径，与实现匹配 |

## 二、通用评审项（六维检查，"怎么查"）

| 维度 | 问什么 | 不通过信号 |
|------|--------|-----------|
| 并发 | 共享资源如何保护？ | 无锁/无乐观锁版本字段/事务内含 IO；竞态未描述 |
| 事务 | 边界与回滚如何定？ | 无 `TRANSACTION_BEGIN` 标记；多表写无一致性描述 |
| 幂等 | 重复提交/重试会怎样？ | 幂等键缺失；消息消费无去重；支付/转账类无幂等表 |
| 异常 | 每层异常如何兜底？ | 依赖失败无降级；异常无错误码；吞异常无日志 |
| 数据模型 | 关系是否合理？ | 冗余列、无索引大表、弱类型字段（JSON 万能）、无约束 |
| 可观测性 | 问题怎么定位？ | 无日志/无 trace/无监控指标；失败不可查 |

## 三、功能链完整性（跨模块）

| 断裂类型 | 检查项 | 等级 |
|---------|--------|------|
| 上游缺口 | 需求侧期望接口 vs 后端规划接口比对 | 缺失=P0 |
| 链路缺失 | A→B→C 流程 B 未实现 | P0 |
| 状态断裂 | 状态机缺逆路径（审核通过→驳回无实现） | P0 |
| 依赖缺失 | 接口依赖的数据来源未定义 | P0 |
| 异常断裂 | 异常流程无兜底逻辑 | P1 |
| 数据断裂 | 接口返回字段在后续未使用 → 确认遗漏 | P1 |
| 上游对齐 | 比对 `doc/arch/` 与 `doc/prd/` 接口完整性 | 缺失=P0 |

## 四、跨端对齐（仅多端）

- 逐端提取接口清单 → 存在性比对（缺失=P0）
- 字段类型对齐（不一致=P1）
- 端间状态流转一致（一端状态多一端少=P0）

## 五、判定

- P0 任一 → ❌ 阻断
- 信息缺失 >30%（字段/错误码/超时缺超一半）→ ❌ 不通过
- P1 >5 项 → ⚠️ 通过但标记修复
