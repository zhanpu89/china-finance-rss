# 评审就绪检查（Check-Common）

> 评审前先验证文档"配不配被审"。**这不是格式检查，是质量门槛**——占位符/空转文档直接拒绝评审，不浪费评审轮次。

## 一、就绪判定（任一不过即返回，不进入正式评审）

| 检查 | 怎么查 | 判定 |
|------|--------|------|
| 文档存在且非空 | `ls doc/` 对应文件，`wc -l` > 0 | 缺失 → ❌ |
| 有标题/版本/状态/日期/作者 | 读头部元数据块 | 缺 → ❌ |
| 背景/目标/核心内容完整 | 读"背景/目标"节，能回答"这文档要解决什么" | 空洞 → ❌ |
| 无占位符 | grep `{例:`/`TODO`/`待补充`/`XXX`/`...` | 关键节占位 → ❌ |
| 字数阈值 | 详设类 < 500 字、PRD 类 < 300 字 = 空转 | 低于 → ❌ |

## 二、空转文档识别（最易漏的坑）

**"看着写了，其实没产出"** 的三种形态：
1. **全占位符**：模板标题在，内容全是 `{例:...}` 或 `待补充`。
2. **复制模板未填**：结构与模板一致，但业务内容为通用话术，无本项目的具体接口/字段/规则。
3. **写满叙述无可执行物**：全是背景散文，却没有一个可执行的接口定义/规则/用例 ID。

**判定：** 空转 = P0 级"根本没产出"，直接 ❌ 阻断，不走正式评审清单。

## 三、信息缺失度粗测

粗扫各节，估算"有实质内容的节 / 应覆盖的节"。**缺失 >30% → ❌ 不通过**，标记缺失节清单返回。
（此判定在进入 check-{模式} 前完成，避免在空文档上跑完整清单浪费上下文。）

## 四、逆向就绪自检（评审者对自己）

- □ 我读的文档版本与作者创作版本一致？（评审隔离：只读文件，不推断意图）
- □ 我确认这是"空转"还是"薄但有核心"？—— 空转阻断，薄但核心完整可进入正式评审
- □ 我知道该加载哪个 check-{模式}，而不是 5 个全读？
