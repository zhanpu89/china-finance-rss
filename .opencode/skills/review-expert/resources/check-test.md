# 测试用例评审（Check-Test）

> 评审目标：测试用例**真的能抓住缺陷**，而不是凑数。对照 `tester/resources/test-patterns.md` 的方法论核查。

## 一、覆盖度与追溯

| 检查项 | 怎么查（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| AC/BR 双向追溯 | 每条 AC/BR 有对应用例；用例能回溯到需求。**有 AC 无用例 = 漏测 P1** | 追溯断裂 = P1 |
| 类型分布 | 反馈:功能 30-40% / 异常 ≥20% / 边界 ≥15% / 性能 ≥5% / 安全 ≥5%；异常占比过低 = 假覆盖 | 分布失衡 = P1 |
| 逆向场景 | 取消失败/超时/重试/降级/并发冲突/幂等重复 有覆盖；只测正常路径 = 假覆盖 | 缺逆向 = P1 |

## 二、方法质量

| 检查项 | 怎么检（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| 用对方法 | 数值字段有边界值（min/max/±1）；多条件规则有判定表；状态流有非法迁移反例 | 只用正例 = P1 |
| 异常四层 | 输入层/依赖层/时序层/数据层是否有覆盖？只盖输入层 = P1 | 漏依赖/时序层 = P1 |
| 用例可判定 | 每条预期能答"通过/失败"，具体值，不是"应该正常" | "应该正常" = P1 |
| 用例独立原子 | 不依赖执行顺序、共享可变状态；可单独重跑结果一致 | 依赖幽灵状态 = P2 |

## 三、数据与环境

| 检查项 | 怎么检 | 缺陷等级 |
|--------|--------|---------|
| 数据策略 | 单测隔离数据/集成独立库；种子基线可重建 | 未知 = P2 |
| 时间/随机控制 | 注入时钟与随机源，避免 flaky 风险 | 时间敏感无控制 = P2 |
| mock 策略 | 外部依赖 mock/fake 清楚，不依赖真实第三方环境 | 依赖真实网络 = P2 |

## 四、缺陷 ID 与阻断

- 用例关联 BUG-ID 完整（BUG-{模块}-{序号} + P0-P3 分级）。
- **含 P0 用例的模块结论必须 ❌ 阻断**，不允许放行。P0 遗漏 = 评审阻断。

## 五、结论判定

- **追溯断裂 / 异常覆盖 <20% / 含未阻断的 P0** → ❌
- **无 P0 但 P1 > 阈值** → ⚠️ 有条件
- **无 P0，P1 ≤ 2** → ✅ 通过
