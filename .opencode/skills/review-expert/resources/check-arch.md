# 架构评审（Check-Arch）

> 每个检查项给"怎么查"，不只列"查什么"。评审的意义是**验证决策经得起推敲**，不是核对格式。

## 一、驱动因素与决策

| 检查项 | 怎么查（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| 模块职责清晰、接口契约完整 | 模块职责边界图/表；接口清单能否被 task-decomposer 直接转 OpenAPI | 缺接口清单 = P1 |
| 技术选型有论证 | 每个选型有 "选 A 因为 X / 不选 B 因为 Y / 何时换 B"。**"A/B 各有优劣"无结论 = P1**（把决策推给下游） | 无论证 = P1 |
| 决策按可逆性分配成本 | 低可逆决策（数据模型/协议/拓扑）有 ADR 深对比；高可逆（端口/版本）快速定 | 低可逆无论证 = P1 |
| 隐藏假设被显式化 | 有"假设 X，当 Y 时架构需变"这类陈述；无假设但有明显前提（量级/一致性）未写 = P1 | 隐藏假设 = P1 |

## 二、数据与一致性（最难的评审点）

| 检查项 | 怎么查（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| 数据模型 | 核心表+关键字段是否覆盖 PRD 实体；字段类型/关系（1:1/N:M）是否明确；唯一约束业务含义说清 | 关键实体缺失 = P1 |
| 一致性方案 | **分布式事务怎么处理**：两阶段/ saga / outbox / 本地消息表？跨服务写操作有没有明确选择？"用分布式事务"没说是哪种 + 失败补偿 = P1 | 无方案 = P1 |
| 幂等 | 写接口幂等键来源（业务键/生成 ID）、去重方式（唯一索引/状态机）、重复请求返回什么 | 无幂等 = P1 |
| 缓存一致性 | 更新顺序（先DB后缓存/先缓存后DB）、失效机制（TTL/主动删）、双写失败兜底 | 缓存与DB无一致性方案 = P1 |
| 数据生命周期 | 软删/硬删、归档、恢复、级联规则有定义 | 生命周期缺失 = P2 |

## 三、可用性与容错

| 检查项 | 怎么查（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| 无单点故障 | DB/缓存/队列/外部依赖每个都问"挂了会怎样"：有备/有降级/有熔断？ | SPOF 无降级 = P1 |
| NFR 已量化 | TPS/P99/RTO/RPO 有数字；"高性能/高可用"等模糊词 = P1 | 模糊 NFR = P1 |
| 重试与熔断 | 第三方依赖重试退避策略、熔断阈值、降级路径是否定义 | 无容错策略 = P2 |

## 四、安全

| 检查项 | 怎么查（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| 认证/鉴权 | 认证方案（JWT/session/OAuth）、token 生命周期、角色权限模型、**水平/垂直越权防护设计** | 越权无设计 = P0 |
| 加密 | 传输 TLS、存储敏感字段（密码/密钥）加密、密钥管理 | 明文存储密钥 = P0 |
| 注入防护 | 输入校验策略、参数化查询、文件上传校验 | SQL注入 = P0 |
| 限流/防刷 | 接口限流策略（QPS/令牌桶）、防暴力破解 | 关键接口无限流 = P2 |

## 五、可观测性与运维

| 检查项 | 怎么查（可操作锚点） | 缺陷等级 |
|--------|---------------------|---------|
| 日志 | 关键链路有结构化日志（traceId/请求ID）、错误日志可定位 | 无 traceId = P2 |
| 监控 | 核心指标（TPS/错误率/延迟）有监控，告警阈值定义 | 无监控设计 = P2 |
| 部署 | 部署拓扑/回滚方案/配置管理明确 | 无回滚 = P2 |

## 六、评审结论判定

- **P0 存在** → ❌ 阻断（安全/数据丢失类）
- **无 P0，P1 > 2** → ⚠️ 有条件（生产版阻断，MVP 降级）
- **无 P0，P1 ≤ 2** → ✅ 通过

**信息缺失 >30% → ❌**（直接标记缺失节，不逐项打分）。
