# 编码纪律规则

> **【通用方法论 · 项目资产】** 本文件随工具分发的版本是跨项目通用的专家标准。安装到项目后，整个 `.opencode/` 即成为你的**项目资产**——可直接改写本文件沉淀团队/项目专属规则，也可在项目 `opencode.json` 的 `instructions` 中增删规则条目。工具不预设任何项目特定内容。

## 1. 先思考再编码
实现前列出假设，不确定就问。有多个解释时列出来，不要默默选一个。

## 2. 简洁优先
不实现未要求的功能，不为单次使用做抽象。200行能写成50行就重写。

## 3. 手术式修改
只改目标代码，不"改进"无关内容。只移除自己改动导致的未用引用。

## 4. 目标驱动
把任务转化为可验证的目标："添加校验" → "写测试让它们通过"。

## 5. 先找模式再编码
编码前，先找到项目中**功能相似**的现有实现，完整读一遍。新代码的命名风格、分层位置、异常处理、参数传递**必须**与现有模式一致。存量项目不打补丁，用存量模式说话。

## 6. 一处数据只改一处
业务数据/实体应有**唯一权威定义**（model/entity 类）。新增字段只在此定义，其他引用位置（DTO/vo/proto/序列化）通过转换或继承自动同步，不做第二份独立定义。修改数据时先搜索所有引用位置，确认没有重复定义后才动手。
